# SOI RIDER · 방콕 오토바이 택시

방콕 소이의 '윈' 오토바이 택시 기사가 되어 배차 앱 **gram** 으로 콜을 받고, 러시아워 차 사이를 비집고 달려
손님을 안전하게 모시는 3D 아케이드 라이딩 게임. Vite 8 · TypeScript 7 (strict) · three.js r186 · pmndrs
postprocessing · 절차적 WebAudio · DOM/CSS UI · Blender 4.5 로 만든 GLB 에셋.

Design: `docs/GAME_DESIGN.md` · architecture & module APIs: `docs/ARCHITECTURE.md` · UI: `docs/DESIGN_SYSTEM.md` ·
assets: `docs/ASSET_SPEC.md`.

## Run

```bash
npm install
npm run dev          # http://localhost:5173  (the game; sandbox/*.html are the per-module dev harnesses)
npm run build        # tsc --noEmit + vite build → dist/ (static, relative paths)
npm run preview      # serve dist/
npm test             # vitest (logic, physics, camera, world, mission, ui, app …)
npm run typecheck
```

The game loop: `BOOT → TITLE → (GARAGE ⇄ SHOP) → SETUP → INTRO (gram call) → PLAY ⇄ PAUSE → RESULTS → next call /
garage / title`. The save (wallet, fuel, loadout, best scores, settings) lives in `localStorage`
(`soi-rider:save:v1`).

### Online ranking (optional)

The title screen's **순위** board ranks riders by their best score. It needs a free Supabase project: run the SQL
in `docs/leaderboard-setup.md`, then copy `.env.example` to `.env.local` and set `VITE_SUPABASE_URL` /
`VITE_SUPABASE_ANON_KEY`. Without them the board runs offline (this device's best only).

## Debug / QA URL parameters

Append to the game URL (e.g. `http://localhost:5173/?skip=play&bot=1&seed=7`):

| Param | Values | Effect |
|---|---|---|
| `seed` | integer | the run's seed (city, traffic, offers, weather) — otherwise random per trip |
| `district` | `sukhumvit` `siam` `silom` `yaowarat` `khaosan` | force the district (trip 1 is always Sukhumvit otherwise) |
| `intensity` | `light` `rush` `gridlock` | Setup's preselected traffic (and the skip default) |
| `tod` | `morning` `noon` `sunset` `night` | force the time of day |
| `weather` | `clear` `haze` `overcast` · `storm` `smog` `calm` | force the sky; `storm` = downpour at 20 % of the trip, `smog` = haze spike at 12 %, `calm` = no events |
| `skip` | `title` `garage` `setup` `intro` `play` `results` | jump straight to a state after boot (no fuel spent; `results` shows a demo receipt without booking it) |
| `job` | 0–2 | which offer `skip=play\|results` takes |
| `bot` | `1` | autopilot: follows the route (pure pursuit), brakes for traffic / signals, filters past queues, stops at the targets, auto-accepts the first call, presses E on prompts |
| `q` | `low` `medium` `high` | pin the quality preset (otherwise Settings › 그래픽 품질, default 자동) |

`window.__game` (test introspection): `state`, `phase`, `fps`, `drawCalls`, `preset`, `mem` (renderer geometries / textures / programs), `config` (seed, district, intensity,
tod, weather + events, trip), `run` (phase, progress, remaining m, km/h, comfort, ETA, time, falls, prompt, care,
weather, bot limit, position, pickup / drop, trait), `result` (grade, total, stars, baht, fail reason), `save`
summary, and `debug.failComfort()` (drops the passenger's comfort to 0 → the run fails).

## End-to-end test

```bash
node tools/e2e.mjs                                 # full trips (7, 23:siam, 5:yaowarat) + fail check + 3×3 sweep
node tools/e2e.mjs --scenario full --seeds 7,11:silom # seed[:district]: boot → title → garage → setup → intro → bot ride → results
node tools/e2e.mjs --scenario fail                 # ?skip=play&bot=1 + failComfort() → F / comfort receipt
node tools/e2e.mjs --scenario sweep                # seeds 3,19,42 × sukhumvit,silom,yaowarat: intro + 20 s of play
```

Headless Microsoft Edge on the GPU (`--use-angle=d3d11`). Screenshots of every state and every 10 s of play go to
`shots/e2e/<scenario>-<seed>/`; the JSON summary lists console / page errors and each RunResult. Exit code 1 on any
error or failed check. The default full-trip seeds are ones the autopilot delivers; it is a QA driver, not a careful
one — on some dense night seeds (e.g. `11:silom`, `31:khaosan`) its slow queue scrapes count as body contacts until the
passenger gets off (the loop still ends cleanly on the F receipt). Single pages / sandboxes:
`node tools/shot.mjs --page "<page>?params" --steps "…"`.

## Assets

Every model is generated by Python scripts in `blender/assets/<group>/*.py` (shared helpers in `blender/lib`) and
exported to `public/assets/models/<name>.glb` (spec: `docs/ASSET_SPEC.md`).

```bash
npm run assets -- blender/assets/vehicles_cars/veh_taxi.py   # = node blender/run-blender.mjs <script>
node tools/glb-inspect.mjs public/assets/models/veh_taxi.glb
```

The runner uses the Microsoft Store Blender 4.5 LTS launcher (override with `BLENDER_BIN`); the launcher does not
forward stdout, so scripts log to `blender/logs/<name>.log`, which the runner prints afterwards. Story key art:
`blender/story/` → `public/assets/story/`.
