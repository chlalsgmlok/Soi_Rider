# Asset Spec (Blender → GLB → three.js) — RUNTIME CONTRACT

Every model is generated by a Python script in `blender/assets/<group>/` using `blender/lib/*`
and exported to `public/assets/models/<name>.glb`. A preview PNG goes to `blender/previews/<name>.png`.
Run one script: `node blender/run-blender.mjs blender/assets/<group>/<script>.py` (prints the log).
Skip the preview render: append `--no-preview`.

## Look
Reference = mockup 03: chunky, rounded, toy-like cartoon 3D ("diorama"), saturated golden-hour palette,
soft bevels on every edge (helpers bevel by default), slightly exaggerated proportions (bigger wheels/heads,
rounder roofs), no textures — flat colours by material, details by geometry (window frames, grilles,
lamp lenses, awning scallops, wire bundles). Colours ONLY from `blender/lib/palette.py`.

## Conventions
- Blender Z-up, metres. Origin = ground (z=0) at footprint centre unless stated.
- Vehicles, bikes, characters FACE **−Y in Blender** (→ +Z forward in three.js).
  Facing −Y, the model's own LEFT is **+X** (so `mirror_L`, `wheel_FL`, `_L` limbs sit at +X); this stays +X in three.js.
- Buildings: facade faces **−Y** (street side), origin at the bottom-centre of the facade line.
- Separate objects only where the runtime needs a node (listed below); join everything else to keep draw calls low.
- Material NAMES are the contract (the game recolours by name). Unlisted materials are fine for fixed colours
  but must not reuse a contract name. Emissive materials use `emission>0` in `mat()`.
- Triangle budgets are enforced with `export_glb(..., max_tris=N)`.

## Shared material names
`Paint`, `Paint2` (secondary body colour), `Trim` (black/dark plastic), `Glass`, `Tire`, `Chrome`, `Seat`,
`Light_Head` (emissive), `Light_Tail` (emissive, dim), `Light_Brake` (non-emissive red; runtime boosts emission when braking),
`Plate`, `Dash_Screen` (bike instrument face — runtime puts a CanvasTexture on it, needs 0..1 UVs),
`Skin`, `Hands`, `Shirt`, `Pants`, `Shoes`, `Hair`, `Hat`, `Helmet_Paint`, `Helmet_Trim`, `Visor`, `Outfit_Paint`, `Outfit_Trim`,
`Poncho`, `Mask`, `Gear_Paint`, `Gear_Logo`, `Wall`, `Wall2`, `Window` (runtime emissive at night), `Shutter`, `Awning_A`, `Awning_B`,
`Sign_Face` (canvas text target; needs 0..1 UVs on a flat quad), `Interior_Light` (warm emissive), `Plastic` (stools, recolourable),
`Canvas` (umbrella fabric), `Leaf`, `Leaf2`, `Flower`, `Signal_Red`, `Signal_Amber`, `Signal_Green`, `Lamp_Glow`.

## Characters (group `characters`), forward −Y, segmented rig (no skinning), stylised (head ≈ 1/5.5 of height)
`char_body` — standing height 1.68 m. Separate objects (parented chain, origin at joint):
`hips` (root, origin at pelvis centre, z≈0.92) → `torso` (origin waist) → `head` (origin neck base);
`torso` → `arm_L` (shoulder) → `forearm_L` (elbow) → `hand_L` (wrist); same `_R`;
`hips` → `thigh_L` (hip joint) → `shin_L` (knee) → `foot_L` (ankle); same `_R`.
Materials: `Skin` (head/neck), `Hands`, `Shirt` (torso, upper arms, forearms), `Pants` (thighs, shins), `Shoes`. Neutral A-pose
(arms ~15° out). Simple face: eyes as small dark ovals, no mouth required. Budget ≤ 2500 tris.
Attachments (origin = attach pivot; attach to node in brackets, offsets zero):
- [`head`] `hair_short`, `hair_long`, `hair_bun`, `hat_cap` (`Hair` / `Hat`), `acc_mask` (`Mask`)
- [`head`] helmets: `helmet_open` (open face + peak), `helmet_full` (full face, `Visor` smoke glass), `helmet_half` (bowl + goggles),
  `helmet_cat` (round with cat ears). Materials `Helmet_Paint`, `Helmet_Trim`, `Visor`. Helmet must fully cover the hair area.
- [`torso`] `outfit_vest` (orange win vest with number patch + reflective stripes: `Outfit_Paint`,`Outfit_Trim`),
  `outfit_hood` (hood + drawstrings, `Outfit_Paint`), `outfit_jacket` (collar, zip, cuffs, `Outfit_Paint`,`Outfit_Trim`),
  `outfit_poncho` (rain poncho over torso+upper legs; when seated it drapes, `Poncho`).
Budget each ≤ 800 tris.

## Runtime fallbacks
If a GLB is missing the game builds a coloured placeholder box with the same nodes/material names (`src/engine/assets/placeholders.ts`),
so code and art can be developed in parallel.
